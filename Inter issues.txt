  Your framing, tightened up
  The transformation itself isn't exotic — it's a source-vs-target comparison like any silver layer CDC process. What makes it hard
  is:                                                                                                                                 
  Scale of the decision space. 120+ columns, and the action type depends on comparing specific subsets of those columns across source 
  and target. It's not one comparison — it's multiple independent comparisons (outlook fields, watch fields, default flags, rating
  symbols) that each produce their own action, and they all have to be evaluated for every record.                                    
  Number of distinct scenarios. You have 15+ action types (OR, OP, WP, WD, DP, DR, DM, WM, UP, DG, AF, NW, CF...), each with its own  
  set of conditions. And these aren't simple flag checks — reinstatement logic alone has to figure out if a withdrawn rating came back
   at the same level (AF), higher (UP), or lower (DG). That requires comparing rating ordinals, not just strings.                     
  Edge cases are the real volume of work:                                                                                             
  - Deduplication when the same rating shows up in both hourly Kafka and daily batch
  - Reinstatement — withdrawn then re-rated, with direction detection                                                                 
  - Same-day reversals (watch placed and removed within one batch)   
  - FCA retroactive corrections against historical data                                                                               
  - History/adhoc backfills that need to replay the same logic against old data                                                       
  - Null handling across PySpark (4 null combinations per field comparison, across many fields)                                       
  - CDC with both rating_id-based windows and action_dt-based windows depending on the scenario                                       
  The real achievement is reliability, not cleverness. Sub-1% monthly error rate across all these scenarios, on 120+ column           
  time-series data, with hourly runs — that's the hard part. Any one rule is simple. Keeping all of them correct together, across edge
   cases, across months of production data, is what took the effort.
