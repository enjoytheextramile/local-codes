Spark

Spark -
 Driver: runs the Spark application main process. Creates Spark Context, builds DAG, splits into stages/tasks, schedules tasks.

 Executors: JVM processes launched on worker machines that execute tasks and store cached data/shuffle data.

 Cluster Manager: allocates resources (CPU/memory) and launches executors (YARN / Kubernetes / Standalone / Mesos).



Who talks to whom:

Driver talks to cluster manager to request executors.

Driver talks to executors to send tasks.

Executors send results/metrics back to driver.

Why we care about lineage and when it can cause issue and checkpointing is required , we can intentionally trigger an action to break DAG and persist data , so the things lineage hold is for crash handling only?



👉 Triggering an action does NOT break lineage.

It only executes the DAG. The DAG (lineage) is still there.

What is lineage actually?

Lineage is Spark’s internal recipe of how to recompute a DataFrame/RDD from source.

Example:

read -> filter -> join -> groupBy -> agg -> window -> ...

Spark stores this as a logical + physical plan (for DF) / dependency graph (for RDD).

Why do we care about lineage?

Because Spark uses lineage for fault tolerance:

If an executor dies and loses a partition, Spark says:

no problem, I’ll recompute that partition using lineage.

That’s the main purpose.

So yes: lineage is heavily related to crash recovery.





1. Long lineage = expensive recomputation

If you have a huge chain of transformations and you do:

df1 = df.transform1().transform2()....transform50()

df1.count()

df1.write.parquet(...)

df1.show()

Even though you already executed .count(), Spark may recompute large parts again for the write/show unless cached/checkpointed.



Why caching/persist is NOT the same as checkpointing



If cached data is evicted (memory pressure) → Spark recomputes using lineage again

Writes data to reliable storage (HDFS/S3)





When checkpointing is required (real scenarios)

🔥 1. Streaming (Structured Streaming)

Checkpoint is mandatory because Spark must store:

offsets
state store info
progress tracking

Without checkpoint → you lose exactly-once guarantees.

🔥 2. Iterative algorithms

Graph processing / ML loops:

 Lineage = recipe

 Cache = keep cooked food in fridge (but can spoil/evict)

 Checkpoint = save cooked food permanently in freezer (and throw away recipe)
